## 2. 板书时光机 P0（录得全、回得准、可恢复）〔历史归档：校验 / 备份 / 恢复条目已随本体移除关闭〕

### 2.1 已具备

| 项 | 实现 |
| --- | --- |
| 事件类型 | `TimelineEventKind` 覆盖笔画/擦除/清空/切页/背景/撤销重做/PPT 翻页与批注/点名/计时/书签/视图 |
| 单调时钟 | `InkRecorder` 使用 `Stopwatch`（`:24`），不依赖墙上时间 |
| 暂停语义 | `Pause/Resume` + `_pausedTotalMs` 扣除（`:79-109`），暂停期间 `AddEvent` 直接丢弃 |
| 橡皮/撤销语义 | 按 `StrokesRemoved` / `Undo` / `Redo` 事件逐条重放（`InkTimeline.ApplyEvent`） |
| 检查点 | 200 事件 / 10s 双阈值（`InkTimeline.cs:35-36`），定位从最近检查点增量重放 |
| 增量落盘 | `SessionJournal` 2s / 50 事件刷盘，JSONL 逐事件追加 |
| 原子写 | `ClassroomSessionStore.Save` 用 `.tmp` + `File.Move(overwrite)` |
| 异常恢复 | `Recover` 合并「快照 + 日志」，忽略截断半行；`PendingSessionIds` 启动提示 |
| 回放一致性 | `EndToEndReplayTests` 16 项（跨页/擦除/撤销/倍速/随机拖动/导出采样） |

### 2.2 缺陷与差距

| ID | 差距 | 影响 | 改造方案 |
| --- | --- | --- | --- |
| P0-1 | `TimelineEvent` 无 `SessionId`、无页面/课件归属字段 | 目标 3.1 明确要求；跨会话合并/导入时无法判定归属 | 新增可缺省 `SessionId`、`PageOwner` 字段，写入时填充；旧数据按会话 Id 补齐 |
| P0-2 | 无事件稳定序号 `Seq`；同毫秒事件仅靠列表插入位置 | 序列化/恢复/导入后同时间事件顺序不稳定，违反 3.2「同时间事件按稳定序号排序」 | 新增 `Seq` 单调序号；时间轴按 `(TimeMs, Seq, 原索引)` 稳定排序 |
| P0-3 | 会话 JSON 无完整性校验，半损坏不可检测 | 目标 3.4 要求「完整性校验」 | 新增 `.sha256` 旁车校验文件，读取时校验，失败降级并从备份恢复 |
| P0-4 | 旧版会话无「迁移前备份 / 可回滚」 | 目标 3.4 与工程约束要求 | `Load` 检测 `Version < 2` 时先写 `.bak`，再字段补齐，失败保留原文件 |
| P0-5 | 回放隔离无显式只读保证 | 3.3 要求「回放中禁止写回原始事件流」 | 回放侧只读断言 + 事件流克隆，禁止反向写入 |
| P0-6 | 「从当前时刻继续板书」未实现 | 3.3 为条件要求（若支持则必须另存） | 明确不提供同会话续写；新增能力一律走新会话（不修改原记录） |
| P0-7 | AI 助教过程事件（识别/求解/贴回/纠错）未作为独立事件类型 | 3.1「如记录 AI 过程」 | 新增独立 `AiStep` 事件类型，独立载荷，不影响基础回放 |
| P0-8 | 事件乱序兜底仅在追加路径，加载/导入无兜底 | 损坏或旧数据可致二分索引失效 | 时间轴构造时统一稳定排序 |

## 3. 板书时光机 P1（长课性能与定位）〔历史归档：结论由插件沿用复核〕

## 6. 分阶段实施方案

1. **阶段 A（AI 图标）**：新建 `AiGlyph` 统一资源工厂 → 替换 4 处硬编码 → 尺寸档位 16/20/24 → 浮窗状态复用 → 首次套索引导。
2. **阶段 B（P0 可靠性）**：事件 `Seq` + `SessionId` + `AiStep` → 稳定排序重建检查点 → `.sha256` 校验 → 旧版迁移备份 → 回放只读断言。
3. **阶段 C（P1 体验）**：键盘快捷键 → 时间轴缩放/缩略 → 分块加载 → 90 分钟压测与定位耗时报告。
4. **阶段 D（P2 导出）**：光标/章节信息选项 → 章节片段 → 隐私提示 → 导出耗时报告。
5. **阶段 E（验证）**：新增单测、构建、全量回归、更新操作说明与验收文档。

每阶段保持独立可回退；Feature Flag 仅用于新增导出/压测等可选能力，核心可靠性改造默认开启。
